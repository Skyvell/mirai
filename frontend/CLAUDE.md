# frontend/CLAUDE.md

Frontend guidance for Claude Code. Product, repo layout, commits, writing and general code style live in the root `CLAUDE.md`; this file covers `frontend/` only.

## Commands

Run from `frontend/` (package manager **pnpm**):

```bash
pnpm dev            # Vite dev server (http://localhost:5173); regenerates the route tree
pnpm build          # tsc -b (typecheck) then vite build
pnpm lint           # oxlint
pnpm generate:api   # re-export the API's OpenAPI schema and regenerate src/client/
```

**Done means `pnpm build && pnpm lint` passes.** Run `pnpm generate:api` first whenever the API contract changed.

## Stack

Vite 8, React 19, TypeScript, TanStack Router (file-based), TanStack Query, Tailwind v4, shadcn/ui (Radix, lucide-react, Geist), Clerk, zod, react-hook-form, date-fns, generated API client (`@hey-api/openapi-ts`). Consult `docs/stack.md` before adding a dependency; respect its `[MVP]`/`[LATER]` tags.

Nine routes: `/` (Overview), `/biomarkers`, `/sources` + `/sources/$uploadId/review`, `/settings`, and placeholders for `/wearables`, `/omics`, `/insights`, `/interventions`. Only biomarkers and lab uploads are in MVP scope.

## Layout

```
src/
├── client/          # Generated API client. Never edit; regenerate.
├── components/      # Shared, feature-agnostic UI.
│   └── ui/          # shadcn primitives (added via the shadcn CLI).
├── features/        # All domain code, one directory per feature.
├── lib/             # Shared non-UI code: API config, math, text helpers.
├── routes/          # File-based routes. Thin config only.
├── routeTree.gen.ts # Generated by the router plugin. Never edit.
├── main.tsx         # Router, QueryClient, Clerk and API wiring.
└── index.css        # Tailwind import and design tokens.
```

**Dependency direction is one way:** `lib/`, `components/` → `features/` → `routes/`. `client/` is a leaf any layer may import. Features never import routes; shared code never imports features.

## Features

Every feature uses the same folders. Omit a folder the feature does not need; never create empty ones.

```
features/<feature>/
├── api/          # Query options, invalidation, polling config, API → domain mappers.
├── domain/       # Pure logic, its types, and vocabularies with their parsers.
├── components/   # React components and plain UI helpers.
├── hooks/        # Client-side React state.
├── pages/        # Route-level components and their search schemas.
└── index.ts      # The feature's public API.
```

`biomarkers` follows this layout. `lab-uploads`, `profile`, `sources` and `overview` already expose an `index.ts` but keep flat internals; migrate each wholesale, in its own commit, when next working in it.

### Folder rules

- **`api/`** — Anything that configures the query cache: `*Options()` wrappers that set `staleTime`, invalidation helpers, polling constants, mappers from generated types to domain types. Components may use generated `*Options()`/`*Mutation()` directly when a wrapper would add nothing. Cache-invalidation knowledge lives in the owning feature, so no call site restates a query key; a feature that must invalidate another's data calls that feature's exported helper (`lab-uploads` calls `invalidateBiomarkerSeries`).
- **`domain/`** — Pure functions, the types they operate on, and vocabularies with their parsers (`BIOMARKER_STATUSES` + `parseStatus`, `BIOMARKER_VIEW_MODES` + `parseViewMode`). Type-only imports from `@/client` are allowed. Being pure, it is the natural unit-test target; no test runner is configured yet.
- **`components/`** — Components plus non-React UI helpers: class names, display labels, badge variants.
- **`hooks/`** — Client-side React state such as persisted preferences. Server state belongs in TanStack Query.
- **`pages/`** — One component per route, rendered by the route file. A page reads params and search via `getRouteApi()` and never imports its route file. The page's search schema sits beside it (`search.ts`; `<page>-search.ts` once a feature has several pages).
- **`index.ts`** — Exports only what routes and other features use. Promote an export when a second consumer needs it; `export *` is off-limits, since it erases the boundary.

No `types/` folder: API types are generated, domain types live with their logic in `domain/`, props stay in their component file.

### Naming

- Files are kebab-case and named for what they are **within their folder**: `components/tile.tsx`, `domain/status.ts`, `pages/biomarkers.tsx`.
- Exports carry the feature noun: `BiomarkerTile`, `BiomarkerStatus`, `BiomarkersPage`, `biomarkerSearchSchema`.
- Vocabulary comes from the design docs: `docs/biomaker_page/biomarker_page.md` names the tile, the row, the bullet graph and the change, so the code does too.
- Named exports only.

### Imports

- **Inside a feature: relative paths** (`../domain/status`).
- **Everything else: `@/`**, and other features only through their index: `import { BiomarkerCombobox } from '@/features/biomarkers'`.
- **Lazy-loaded modules** (`React.lazy`, dynamic `import()`) import the file directly so it stays in its own chunk. Never re-export a lazy module from `index.ts`: a static re-export pulls it back into the importer's chunk.
- `import/no-cycle` is an error; if two features need each other, move the shared code to `lib/` or a shared `domain/`.

### Enforcement

`no-restricted-imports` in `.oxlintrc.json` makes the boundaries lint errors:

- **Everywhere:** `@/features/*/**` — deep imports into a feature. Dynamic `import()` is outside the rule's scope, which is what lets the lazy exception stand without a disable comment.
- **`src/features/*/domain/**`:** additionally `react`, `cn`, `@/components/**`, runtime imports from `@/client/**` (type imports pass), and `../api`, `../components`, `../hooks`, `../pages` — the layers built on top of `domain/`. The override restates the feature-boundary pattern, because an override replaces a rule's options.

Patterns use `**`: a single `*` matches one path segment, so `@/features/*/*` would miss `@/features/biomarkers/domain/status`.

**Barrels depend on `"sideEffects": ["**/*.css"]` in `package.json`.** It tells the bundler that importing a JS module runs nothing worth keeping, so unused re-exports drop out. Without it, `_authenticated.tsx` importing `biomarkersOptions` from `@/features/biomarkers` dragged the whole biomarkers page into the entry chunk (467 kB → 580 kB), because the page runs `getRouteApi()` at module scope. A module that genuinely must run for its side effects has to be listed there.

### New feature

A directory under `features/` following the layout above, a thin route file under `routes/`, and the page exported from `index.ts`.

## Routing

TanStack Router, file-based: a file under `src/routes/` becomes a URL. `__root.tsx` is the Clerk boundary only. The pathless `_authenticated.tsx` holds the profile gate and nav shell; every gated route lives under `routes/_authenticated/` without an `_authenticated` URL segment. Route files contain `createFileRoute` plus `validateSearch`/`loader`/`beforeLoad` and render a feature page in one line.

`queryClient` is absent from router context; add it (`createRootRouteWithContext`) when the first route needs `loader` prefetch.

## API client

`src/client/` is generated by `pnpm generate:api` and committed (CI is pnpm-only); the intermediate `openapi.json` is gitignored. It exposes a typed SDK and `*Options()`/`*Mutation()` TanStack Query helpers keyed on the backend's `operation_id`s. The client configures itself via `runtimeConfigPath` → `createClientConfig` in `src/lib/api.ts` (`baseUrl` from `VITE_API_URL`, Clerk token attached only to Bearer-secured operations). `apiErrorMessage` surfaces FastAPI's `detail`.

Query defaults (`main.tsx`): `staleTime` 5 min, no focus refetch, 6 retries with exponential backoff capped at 5 s. The backend scales to zero, so retries cover cold starts; keep them. Data refreshes through explicit invalidation, except the Sources report list, which polls while an upload is `queued`/`processing` (`IN_PROGRESS` and `POLL_MS` in `lab-uploads/status.ts`).

The API sends decimals as strings (`BiomarkerMeasurementRead.value`, `BiomarkerIntervalRead.low`/`.high`). Parse with `Number()`, and guard nullable fields first: `Number(null)` is `0`, which would turn an unbounded interval bound into zero.

Use generated types rather than restating API shapes. Tie runtime literals to them with `satisfies` so a backend change fails the build.

## Auth

`ClerkProvider` wraps the app in `main.tsx`; `ApiProvider` injects Clerk's `getToken` into the API client. Gating happens in the component tree: signed-out users see `<SignIn/>` from `__root.tsx`, users without `sex` and `date_of_birth` see the onboarding gate from `_authenticated.tsx`.

Build config (`VITE_API_URL`, `VITE_CLERK_PUBLISHABLE_KEY`) lives in the committed `.env`; both values are public. A gitignored `.env.local` overrides it for a local API.

## Styling

Tailwind v4 with shadcn tokens in `src/index.css`. Colors are defined in `:root`/`.dark` and mapped to Tailwind in `@theme inline`. **Re-theme by editing `:root`/`.dark`, never the `@theme` mapping.** Add shadcn components with `pnpm dlx shadcn@latest add <name>`; they land in `components/ui/`. `cn` comes from the `cn` package and resolves Tailwind conflicts, so a `className` override wins over a component's base classes. The `@/*` alias is declared in both `vite.config.ts` and the tsconfigs on purpose (bundler vs. typechecker and shadcn CLI).

## Hosting

Static SPA on Cloudflare Pages (`https://mirai-web.pages.dev`), deployed by `.github/workflows/_deploy-frontend.yml` via `wrangler pages deploy`. Deployment uses a Pages-scoped API token held in CI, deliberately in place of the Cloudflare GitHub App, which would grant a third party write access to this auto-deploying repo. `public/_redirects` serves the SPA catch-all. The API's CORS allow-list (`frontend_origins` in `infra/opentofu/environments/<env>/main.tf`) must include every origin the frontend is served from, so per-deployment preview URLs cannot reach the API.

## Conventions

- Comments explain why: a non-obvious constraint or a deliberate choice. Keep existing why-comments when refactoring (cold-start retries in `main.tsx`, chunk splitting).
- Keep modules off the shell's critical path: anything rendered once or behind a dialog is lazy-loaded.
